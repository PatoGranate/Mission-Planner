Each body in a system has its individual reference frame. When the satellite orbits around Earth, we use an ECI, (earth centred inertial) reference frame, which simply considers the centre of the earth at the point (0, 0, 0), and takes the global positions of the satellite around it. However, the satellite itself has an orientation, and we need to be able to orient it correctly in order to do anything useful with it; having a satellite that has its camera pointing at empty space isn't of much use. 

In order to do this, we define a frame of reference for the satellite, which, as any other reference frame has three axes. The z-axis is pointing in the direction of the camera, such that where the z-axis points towards is what the camera will see. We want the x-axis to point in the direction of motion (arbitrarily), but there is a problem with simply setting the x-axis equal to the velocity vector. For non-circular orbits, nadir pointing and velocity are not perpendicular. To go around this problem, the velocity vector is projected onto the locally (with respect to the already defined nadir pointing z-axis) horizontal plane, and that projected velocity is what defines the x-axis. With the x and z axes defined, y is defined as the only perpendicular vector to the XZ plane.

```python
# Take the vector position of the satellite, and normalize it to determine the satellite's z-axis: b3
from org.hipparchus.geometry.euclidean.threed import Vector3D

# Calculate the unit vector nadir pointing at t = 0
r0 = Vector3D(float(poses[i,0]),
			  float(poses[i,1]),
			  float(poses[i,2]))
r0_mag = r0.getNorm()
b3_unit = r0.scalarMultiply(1/r0_mag)

# Calculate the unit vector pointing in direction of motion
v0 = Vector3D(float(vels[i,0]),
			  float(vels[i,1]),
			  float(vels[i,2]))
b1 = v0.subtract(b3_unit.scalarMultiply(v0.dotProduct(b3_unit)))
b1_unit = b1.scalarMultiply(1/b1.getNorm())

# Calculate remaining third vector
b2_unit = b3_unit.crossProduct(b1_unit)

# Store vectors in direction cosine matrix from eci to body
DCM_b2e = np.array([(b1_unit.x, b1_unit.y, b1_unit.z), 
					(b2_unit.x, b2_unit.y, b2_unit.z), 
					(b3_unit.x, b3_unit.y, b3_unit.z)])
```

This results in two different 3-axis systems. In order to do anything with this information, we need to store it such that we know where the satellite is pointing at any given point in time. However, these are stored in DCM's, which have 9 arguments, and therefore inefficient to store. In order to get around this, we can use quaternions, which only require 4 arguments, and store the same information. 

A quaternion describes the amount of rotation of a body along a specified vector, starting from it's initial position to arrive at a desired orientation. This can be thought of as: in what direction, and by how much do I have to rotate the inertial (normal x, y, z axis of the earth) frame of reference in order to arrive at the satellite's current frame of reference (b1, b2, b3 axes)? This is the information stored in the quaternion, and is applied as follows:

```python
from scipy.spatial.transform import Rotation as R

DCM_b2e = np.array([(b1_unit.x, b1_unit.y, b1_unit.z), 
					(b2_unit.x, b2_unit.y, b2_unit.z), 
					(b3_unit.x, b3_unit.y, b3_unit.z)])

quat = R.from_matrix(DCM_b2e).as_quat()
quats[i] = quat
```
